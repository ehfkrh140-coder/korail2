# KTX 잔여석 모니터링 알림판

이 프로젝트는 단순 타이머 앱이 아닙니다. 지정한 날짜·구간·시간대의 KTX 열차를 로컬 서버가 일정 간격으로 실제 조회하고, 조회 결과에서 일반실·특실·입석·자유석 가능 상태가 발견될 때만 화면과 소리로 알려주는 **로컬 잔여석 모니터링 알림판**입니다.

> 시간이 지나면 알림을 울리는 것 ❌<br>
> 시간이 지나면 실제 잔여석을 조회하고, 잔여석이 있을 때만 알림을 울리는 것 ✅

## 하는 일

- `http://localhost:3001` 로컬 웹앱을 제공합니다.
- `/api/check-once` API로 조건별 KORAIL 열차 조회를 즉시 1회 수행합니다.
- `/api/monitor/start` API로 여러 조건을 보수적인 주기로 반복 조회합니다.
- 조회 결과 HTML을 파싱해 열차별 상태를 구분합니다.
  - 매진
  - 예약대기
  - 입석 가능
  - 일반실 예매 가능
  - 특실 예매 가능
  - 자유석 가능
  - 조회 실패 또는 서버 응답 오류
- 잔여석 후보가 발견된 경우에만 화면 강조, 반복 알림음, 브라우저 알림을 제공합니다.

## 하지 않는 일

- 자동 로그인하지 않습니다.
- 자동 예매하지 않습니다.
- 자동 예약 버튼 클릭을 하지 않습니다.
- 자동 결제 또는 좌석 자동 선택을 하지 않습니다.
- CAPTCHA, 보안 확인, 매크로 탐지, CODE -8003 오류를 우회하지 않습니다.
- 비정상적으로 빠른 반복 요청이나 대량 병렬 요청을 하지 않습니다.

잔여석 발견 후 실제 예약, 결제, 좌석 선택은 사용자가 KORAIL 사이트 또는 코레일톡에서 직접 진행해야 합니다.

## 기본 모니터링 조건

화면에서 값을 수정할 수 있으며, 여러 조건을 동시에 관리합니다.

| 구분 | 날짜 | 구간 | 시간 범위 | 승객 |
| --- | --- | --- | --- | --- |
| 조건 1 | 2026-05-23 | 광명 → 부산 | 09:00 이상 13:00 이하 | 입력 가능 |
| 조건 2 | 2026-05-24 | 부산 → 광명 | 입력 가능 | 입력 가능 |

## 조회 간격 정책

- 기본 조회 간격은 60초입니다.
- 최소 조회 간격은 20초입니다.
- 20초 미만을 입력하면 서버와 화면에서 모두 거부합니다.
- 조회 실패 시 즉시 무한 재시도하지 않고 다음 예약 주기까지 기다립니다.
- 각 주기에서는 설정된 조건을 순서대로 조회하며, 자동 예매나 결제 요청은 보내지 않습니다.

## 파일 구조

```text
korail-ktx-seat-helper/
├─ server.js
├─ package.json
├─ src/
│  ├─ korailClient.js
│  ├─ monitor.js
│  └─ parser.js
├─ tests/
│  └─ parser.test.js
└─ public/
   ├─ index.html
   ├─ app.js
   └─ styles.css
```

- `server.js`: 로컬 서버 실행, 정적 파일 제공, API 라우팅
- `src/korailClient.js`: KORAIL 조회 요청 생성 및 응답 파싱 호출
- `src/monitor.js`: 보수적인 주기 조회 루프와 상태 관리
- `src/parser.js`: 조회 결과 HTML에서 열차와 좌석 상태 판별
- `public/index.html`: 화면 구조
- `public/app.js`: 버튼 제어, 상태 표시, 알림음/브라우저 알림
- `public/styles.css`: 알림판 디자인

## 설치 및 실행

외부 npm 의존성이 없으므로 `npm install` 없이 실행할 수 있습니다. Node.js LTS 버전을 설치한 뒤 아래 명령을 실행하세요.

```bash
npm run dev
```

브라우저에서 다음 주소를 엽니다.

```text
http://localhost:3001
```

종료하려면 실행 중인 터미널에서 `Ctrl + C`를 누릅니다.

## API

### `POST /api/check-once`

현재 조건으로 즉시 1회 조회합니다.

```json
{
  "conditions": [
    {
      "id": "gwangmyeong-busan",
      "from": "광명",
      "to": "부산",
      "date": "2026-05-23",
      "startTime": "09:00",
      "endTime": "13:00",
      "passengers": 1
    }
  ]
}
```

### `POST /api/monitor/start`

모니터링을 시작합니다. 시작 시 즉시 1회 조회하고, 이후 설정 간격으로 다시 조회합니다.

```json
{
  "intervalSeconds": 60,
  "conditions": [
    {
      "id": "gwangmyeong-busan",
      "from": "광명",
      "to": "부산",
      "date": "2026-05-23",
      "startTime": "09:00",
      "endTime": "13:00",
      "passengers": 1
    }
  ]
}
```

### `POST /api/monitor/stop`

모니터링을 중지합니다.

### `GET /api/monitor/status`

현재 모니터링 상태, 마지막 조회 시각, 다음 조회 예정, 조건별 결과를 반환합니다.

## 화면 사용 방법

1. 조건 입력 영역에서 출발역, 도착역, 날짜, 시작 시간, 종료 시간, 승객 수를 확인합니다.
2. 조회 간격이 20초 이상인지 확인합니다.
3. `즉시 1회 조회`를 눌러 현재 조건으로 실제 조회를 한 번 수행합니다.
4. `모니터링 시작`을 누르면 각 주기마다 실제 조회를 수행합니다.
5. 잔여석이 없으면 조용히 다음 주기를 기다립니다.
6. 잔여석이 발견되면 큰 알림 영역과 반복 알림음이 켜집니다.
7. `알림음 중지` 버튼으로 소리를 멈춥니다.
8. 사용자가 직접 KORAIL 또는 코레일톡에서 예약/결제를 진행합니다.

## 자주 발생하는 문제

### `조회 실패`가 표시됩니다

네트워크, KORAIL 응답 제한, 예약 가능 기간, 명절 예매 제한, 서버 장애 등으로 실패할 수 있습니다. 프로그램은 즉시 무한 재시도하지 않고 다음 주기에 다시 조회합니다.

### `대상 KTX 열차를 찾지 못했습니다`가 표시됩니다

날짜, 시간, 역 이름, 예약 오픈 여부를 확인하세요. KORAIL 화면 구조가 변경된 경우 파서 수정이 필요할 수 있습니다.

### 알림음이 계속 울립니다

잔여석이 발견된 상태입니다. 화면의 `알림음 중지` 버튼을 누르세요. 자동 예매는 수행하지 않습니다.

### 3001 포트가 이미 사용 중입니다

다른 포트를 지정해 실행할 수 있습니다.

```bash
PORT=3002 npm run dev
```
